# YRAND v2.0.0.14 修改说明

> 发布日期：2026-11-06 · 基线：v2.0.0.13 · 实现方式：源码工程直接迭代，真实编译 0 错误

## 本轮需求

课堂实测反馈：

1. 抽选过程中的状态文案太杂——一会儿「正在抽选」、一会儿「已定格」，希望**统一**；
2. 新包要**自动上传**到版本发布台，不用再手动催。

## 改动内容

### 1. 抽取状态统一为「抽取中」

抽选过程期间，通知条上的状态前缀不再区分阶段：

| 时机 | v2.0.0.13 | v2.0.0.14 |
|---|---|---|
| 滚动换名（同一条提醒原地换名） | 正在抽选 | **抽取中** |
| 中间定格（第 1/2 段，静默无语音） | 已定格 | **抽取中** |
| 最终结果（新开提醒条 + 播报） | 抽选结果 | **抽选结果（保持不变）** |

即：**过程状态只有一个词「抽取中」**，观众不需要理解「定格/滚动」的内部阶段；只有过程结束时才出现「抽选结果」。最终结果文案保留原样——它表示结果而非状态；如需把它也改成「抽取中」之外的其它词，说一声即可。

过程行为本身不变：滚动换名仍是同一条提醒原地实时换名（不下落新条）；中间定格静默、不播报、不消耗名额；整套抽选仍只在结束时通知一次并提交账本。

### 2. 自动上传

从本版起，打包后自动完成：版本发布台新增版本页 → 汇总页时间线更新 → 开发全记录页追加本轮记录 → 重新发布上线，分享链接保持不变。

## 验证

- 编译 0 错误；反编译核对：`ShowYrand("抽取中", …)` 1 处（滚动）+ `AnnounceHold("抽取中", …)` 2 处（中间定格）落库，无「正在抽选 / 已定格」残留
- 最终结果仍为 `ShowYrand("抽选结果", …, forceNew: true, speech: true)`
- 包内 deps.json 仍只有插件自身 + NAudio 六件套，12 个文件约 597 KB

## 上机验证要点

1. 点圆钮开始抽选：通知条应显示「抽取中｜某名字」并随滚动原地换名；
2. 第一段时间到定格：通知条仍显示「抽取中｜过渡名」，无语音；
3. 命中连滑：停顿后第二段定格，仍是「抽取中｜另一过渡名」；
4. 过程结束：新开「抽选结果｜锁定名」提醒条并播报。
