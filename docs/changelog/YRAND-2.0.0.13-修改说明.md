# YRAND v2.0.0.13 修改说明

> 日期：2026-11-06 · 基线：v2.0.0.12（完整源码工程上继续迭代，真实编译 0 错误）

## 一、本轮修复的三个问题（课堂实测反馈）

| # | 反馈 | 根因 | 修复 |
|---|---|---|---|
| 1 | 「我要滚动效果」 | v2.0.0.10 落地「零消耗表演」时，把滚动期间的同一条提醒原地换名（`AnnounceRolling`）也一并删掉了，通知层面全程静默 | **恢复滚动换名**：`Timer_Tick` 滚动取样后调用 `AnnounceRolling(name)`，同一条提醒原地实时换名，不下落新条 |
| 2 | 「两轮抽选在这一版没有体现」 | 连滑的第二段既没有滚动，每段定格又都显示同一个锁定名——画面从「定格」到「定格」毫无变化，观众看不到第二轮 | **中间定格改显示过渡名**：新增 `PickTransitionName()`，用同源公平分布取样（零消耗），并刻意避开锁定名防止提前剧透。每一段都有「定格 → 停顿 → 再定格」的可见节奏，最终结果在最后一段揭晓 |
| 3 | 「不需要把指纹也注册到通知」 | v2.0.0.10 把指纹拼进了结果通知前缀「抽选结果 · 指纹 XXXX」 | **通知去指纹**：结果通知前缀恢复为「抽选结果」；指纹仅保留在悬浮窗 Tooltip 供复核与复算 |

## 二、修复后的完整过程编排

```
点击圆钮
  → 生成种子、锁定唯一结果（locked，不揭示）
  → 第一段滚动：通知条「正在抽选：XX」原地实时换名
  → 定格过渡名 A（通知条原地改「已定格：A」，不播报）
  → 连滑判定（基础概率 + 麦克风声浪加成）命中
  → 停顿 gap → 定格过渡名 B → 停顿 → …
  → 某段未命中 / 达连续上限 / 等待中手动点圆钮
  → 定格 locked → 新开一条「抽选结果：最终名」+ 语音播报 → 提交账本
```

关键性质保持不变：

- **中间定格静默**：不播报、不新建通知条（原地改前缀属于同一条提醒的更新）、不消耗「本轮不重复」名额；
- **结果锁定**：中签者仍是点击瞬间由公平算法锁定的人，过渡名、滑动概率、麦克风音量、手动点击时机都改变不了它；
- **公平账本**：每套过程仍然只消耗 1 个名额，`PickedCounts` 等数值验证结论（N=10 抽 1000 次偏差 ≤1）不受影响。

## 三、改动清单

- `Views/YrandWindow.cs`
  - `Timer_Tick`：恢复 `_host.AnnounceRolling(name)`（滚动换名）
  - 新增 `PickTransitionName()`：过渡名取样 + 避开锁定名（重试一次）
  - `Determine` / `AnnounceNext`：连滑分支定格过渡名，并调用 `AnnounceHold("已定格", 名, speech: false)`；未命中走 `FinishEpisode()`
  - `FinishEpisode`：定格 `_lockedName` 后通知播报（等待中手动点圆钮同此路径）
- `Services/YrandHostService.cs`
  - `Announce`：移除指纹前缀，恢复「抽选结果」；`Commit()` 保留
  - `AnnounceHold`：新增 `bool speech = true` 参数（中间定格传 false，最终结果仍播报）

## 四、上机验证建议

1. 点圆钮：通知条应下落一次并随滚动实时换名；
2. 第一段定格：通知条原地变「已定格：某过渡名」，**无语音**；悬浮窗圆窗同步显示过渡名；
3. 命中连滑时：能看到第二段定格出**另一个**过渡名（两轮抽选可见）；过渡名不应提前出现最终结果；
4. 过程结束：新开「抽选结果」提醒并播报**锁定名**，通知上无指纹；
5. 连续抽 20 次，`settings.json` 的 `PickedCounts` 各人仍应贴近均分。
