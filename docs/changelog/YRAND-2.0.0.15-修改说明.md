# YRAND v2.0.0.15 修改说明

> 发布日期：2026-11-09 · 基线：v2.0.0.14 · 实现方式：源码工程直接迭代，真实编译 0 错误

## 本轮需求

课堂实测反馈：**v2.0.0.14 滚动太快时会出现重复触发弹窗**——快速滚动（尤其开启麦克风提速后，最快约 97ms 一换名）时，提醒条反复弹出、互相顶掉。

## 根因

过程通知的存活判断依赖 `CompletedToken` 回调清空引用：弹窗被系统关闭/完成的那一刻引用即被置空，下一次换名（最快 97ms 后）就判定「无存活通知」，走**重新注册**路径——新请求把还没渲染完的旧条顶掉。滚动越快，重新注册越频繁，表现为弹窗反复触发。

## 修复（过程通知显式化，只注册一次）

新增三个方法，滚动/定格换名与「注册通知」彻底解耦：

| 方法 | 职责 |
|---|---|
| `BeginEpisodeNotification()` | 点圆钮开始抽选时注册**唯一一条**过程通知（EndTime 覆盖整场）；已存在则跳过 |
| `UpdateEpisodeName(name)` | 滚动换名、中间定格：**只改控件属性**（`Model.Prefix/Name`），通知已结束则静默跳过，绝不重新注册 |
| `EndEpisodeNotification()` | 过程结束时关闭过程通知，由「抽选结果」新条接管（`Announce` / `AnnounceStatus` 内部先调用） |

删除了 `AnnounceHold` / `AnnounceRolling`（旧入口会被 CompletedToken 时机牵着走），`ShowYrand` 对结果/错误通知的原有注册机制一行未动。

## 修复后行为

- 点圆钮 → 注册一条「抽取中｜」过程通知 → 滚动原地换名（再快也只是改属性）→ 中间定格原地换名 → 结束时关闭它、新开「抽选结果｜锁定名」+ 播报
- **全程最多 2 次弹窗**：过程开始 1 次 + 结果 1 次；滚动无论多快都不产生新弹窗
- 若过程通知被系统/用户中途关闭，后续换名静默跳过（悬浮窗圆钮仍显示名字），不补弹——宁缺毋滥
- 抽选状态机、公平算法、麦克风加成、过程时长全部未动

## 验证

- 编译 0 错误；反编译核对：`BeginEpisodeNotification` / `UpdateEpisodeName`（确认实现体只含属性赋值）/ `EndEpisodeNotification` 全部落库，旧入口无残留；`ShowYrand` 中 `ShowNotification` 调用点数量不变
- `YrandWindow` 4 处调用点确认：开始注册 1 次、滚动与两处定格均为 `UpdateEpisodeName`
- 包内 deps.json 仍只有插件自身 + NAudio 六件套，12 文件约 597 KB

## 上机验证要点

1. 开启麦克风声浪加成、对着麦克风制造持续声浪（滚动最快档），点圆钮抽选：全程应只有过程开始那一条弹窗在原地换名，不出现第二条；
2. 命中连滑时：停顿后原地换出过渡名，同样不弹新条；
3. 过程结束：恰好出现一次「抽选结果」弹窗并播报；
4. 快速连点圆钮多次抽选：每套过程各一条过程通知 + 一条结果，不叠加。
